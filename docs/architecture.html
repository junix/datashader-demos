产品概览

一句话定位 + 核心能力清单

datashader-demos 是一个演示性质的 Python 包，专注于展示 Datashader 栅格聚合（raster aggregation）在大数据量下的可视化能力。当数据量大到无法逐点绘制时，Datashader 先在画布栅格上做聚合统计，再把聚合结果映射为颜色——这让百万级乃至更高量级的数据渲染成为可能。

项目输出 12 个独立场景的透明 PNG 图像，每个场景附带像素级校验与元数据清单（manifest），确保输出质量稳定、可重复。所有数据均为确定性合成数据集（deterministic synthetic fixture），不依赖外部数据源。

项目代码量约 700 行，集中在两个文件中：cli.py 与 render.py。这是一个典型的「薄壳 + 厚内核」结构——CLI 层只做参数解析与调度，渲染层承载全部业务逻辑。

cli.py（约 50 行）是项目的入口层。它用 argparse 定义了 render、validate、list 三个子命令，将用户输入转化为对 render 模块的函数调用。它不直接操作图像或数据，职责单一。

render.py（约 640 行）是项目的核心。它包含三部分内容：① 数据结构定义（Demo、PixelStats）与 DEMOS 注册表；② 12 个场景渲染函数，每个函数内部完成「合成数据 → Datashader 聚合 → 着色 → 装饰 → 输出」的完整管线；③ 像素级校验函数与主渲染调度函数。

第三方依赖有四个：datashader 负责栅格聚合与颜色映射，是项目的核心能力来源；numpy 负责合成数据生成与像素统计；pandas 负责把合成数据封装为 DataFrame 供 Datashader 消费；pillow 负责在图像上绘制标题、图例等装饰元素，并输出 PNG 文件。

catalog.json 是一个独立的元数据索引文件，为 12 个场景提供了按用途、系列、复杂度、标签检索的能力，与代码中的 DEMOS 注册表形成「代码即真相 + JSON 可检索」的双轨结构。

每一个场景的渲染都遵循同样的六步管线。这条管线的设计哲学是：数据生成与渲染完全解耦，每一步的输出都是下一站的标准输入。

第一步：CLI 调用。用户执行 datashader-demos render point-density，CLI 解析参数后调用 render_demo() 函数。可以通过 --rows 覆盖默认行数，也可以指定任意子集的场景名称。

第二步：合成数据。每个渲染器内部用 NumPy 生成确定性数据——固定随机种子（如 42、84、73 等）确保每次运行输出完全一致。数据形态因场景而异：点场景生成二维坐标数组，轨迹场景生成带路径 ID 的时序点列，分形场景则在复数网格上做牛顿迭代。

第三步：DataFrame 封装。合成好的 NumPy 数组被封装为 Pandas DataFrame。对于分类场景（category-mix、fractal-basin、event-raster 等），还会用 pd.Categorical 声明类别列，供 Datashader 的 count_cat 聚合器使用。

第四步：栅格聚合。这是 Datashader 的核心能力。ds.Canvas 定义画布尺寸与数据坐标范围，canvas.points() 或 canvas.line() 将数据点/线投影到栅格上，并用指定的聚合函数（count、count_cat、mean）统计每个像素的值。输出是一个 xarray 二维数组（aggregation）。

第五步：颜色映射。tf.shade() 将聚合值映射为颜色。关键参数是 cmap（色带）、how（映射方式：eq_hist 等直方图或 linear 线性）和 min_alpha（最低透明度，确保稀疏数据也可见）。部分场景还使用 dynspread 或 spread 做像素扩展，让稀疏点更醒目。

第六步：图像装饰与输出。着色后的栅格被贴到一张 1600x1000 的透明画布上，Pillow 绘制标题、副标题、图例、行数标注与来源说明。最终保存为 PNG，同时生成同名 JSON 清单并执行像素级校验。

12 个场景可归入六个族系。每个族系共享相似的聚合策略与数据组织方式，但在业务语义和视觉表达上各有侧重。

点聚合族是最基础的 Datashader 用法——把大量二维点投影到栅格上计数，用颜色深浅表示密度。point-density 场景用 200 万个点演示了五个重叠分布的聚集模式。

轨迹族使用 canvas.line() 而非 points，数据组织为带 NaN 分隔符的连续坐标序列（NaN 的作用是切断路径，防止 Datashader 把上一条轨迹的终点与下一条的起点相连）。trajectory-bundle 和 phase-portrait 都属于这一类。

类别聚合族在计数的同时按类别分色，核心是 count_cat 聚合器。这一族场景最多——category-mix（四群体领地）、fractal-basin（三牛顿根盆地）、event-raster（三级严重度事件）、rare-outliers（基线/稀有），共四个场景。

网络与路径族同样是线聚合，但数据生成的语义不同——不是运动轨迹，而是节点间的曲线连接。network-density 演示了全连接网络的边密度走廊，geo-routes 则模拟了地理起终点对之间的弧形航线。

迭代与参数族的特点是数据不是随机生成的，而是通过数学迭代产生。fractal-basin 用牛顿法在复数网格上迭代求根，parameter-sweep 用逻辑映射做分岔图。它们在聚合方式上属于点聚合或类别聚合，但数据来源是确定的数学过程。

标量与不确定性族使用非计数聚合器。terrain-scan 用 mean("z") 做平均高程聚合，uncertainty-fan 则是系综路径的线密度图——这两个场景分别代表了「标量场」和「概率分布」两种常见的非计数可视化需求。

质量保证体系

从像素校验到测试闭环的多层质量防线

图 4 · 质量保证三层防线

项目采用三层质量防线，确保渲染结果可靠、可复现、可追踪。

第一层：像素级校验。validate_png() 函数在每次渲染完成后立即执行。它用 NumPy 直接读取 PNG 的 RGBA 数组，统计三个关键指标：透明像素占比（确保背景透明而非意外填白）、可见像素数量（确保有实际内容而非空白图）、彩色像素数量（确保数据有色差而非单色灰度）。任一指标不达标就抛出 ValueError，渲染即告失败。这是最基础也最迅速的质量闸门。

第二层：元数据清单。每张 PNG 旁边都有一个同名 JSON 文件，记录了场景名称、标题、请求行数、渲染耗时、像素统计、背景类型与数据来源。这份清单不仅是文档——它还是自动化质量追踪的数据源，可用于跨版本比对渲染性能退化或像素分布异常。

第三层：pytest 测试套件。测试文件包含两类测试：广度测试检查 DEMOS 注册表中至少有 12 个场景且副标题有足够多样性，防止新增场景时意外删除或重复；渲染测试对全部 12 个场景做参数化遍历，每个场景用 2.8 万行小数据量快速渲染，验证输出尺寸正确、透明像素充足、JSON 清单存在。这层测试在 CI 中运行，确保代码变更不会破坏任何场景。

三层防线各司其职：像素校验在运行时守护单张图像的质量，元数据清单提供可审计的历史记录，pytest 则在代码变更时做全场景回归检查。

主走查：点密度渲染

从命令行回车到 PNG 落地的五步全流程

图 5 · 主走查：point-density 端到端渲染流程
1

CLI 解析与调度

用户执行 datashader-demos render point-density。argparse 识别出 render 子命令和场景名 point-density，校验场景名存在于 DEMOS 注册表后，调用 render_demo("point-density", Path("out"))。

2

确定性数据生成

进入 _point_density() 函数。使用种子为 42 的 NumPy 随机数生成器，创建 200 万个点——5 组不同中心和尺度的二维高斯分布，再叠加正弦调制使分布形态更自然。最终封装为带 x、y 两列的 Pandas DataFrame。

3

栅格聚合与着色

创建 1420×760 的 Datashader Canvas，坐标范围 x∈[-7.5, 7.5]、y∈[-5.2, 5.2]。调用 canvas.points(frame, "x", "y", agg=ds.count()) 做栅格计数，得到二维聚合数组。再用 tf.shade() 以等直方图（eq_hist）方式映射到六色色带，min_alpha=25 确保稀疏区域仍可见，最后 dynspread 让高密度点适度扩散。

4

装饰合成与文件输出

着色后的栅格被贴到 1600×1000 的透明画布上（偏移 90, 170）。Pillow 在顶部绘制品牌标签、标题、副标题、行数标注，在底部绘制四色色例与数据来源说明。最终以 optimize=True 保存为 PNG，同时写入包含渲染耗时和像素统计的 JSON 清单。

5

像素校验与结果反馈

validate_png() 读取刚保存的 PNG，用 NumPy 计算透明像素占比、可见像素数、彩色像素数。三项全部通过后，CLI 打印一行摘要（文件名、尺寸、透明像素数），整个渲染流程结束。
